# 仿真 vs MAV6D 标注一致性核对（2026-09-15）

起因：纯仿真模型 S1 零样本测 MAV6D test 位置误差 4.04 m、角度误差 90.9°，而同一模型在仿真 test 上是 0.17 m / 5.0°。
用户要求核对两边标注是否一致、链路手算验证，然后训练看效果，不好再分模型原因还是数据原因。

## 结论一览

| 项目 | 仿真（UavIndoorSim → indoor8） | MAV6D | 状态 |
|---|---|---|---|
| 相机系 / 手性 / CARLA→OpenCV | 角点左手 → 翻宽度轴，x 前 y 左 z 上 | 四元数 + camera2vicon，x 前 y 左 z 上 | 一致（手算走查 31 项全过） |
| 内参 | im_info 为扰动假值，已换回真值 | 去畸变针孔，每帧 K_in | 一致 |
| 标签与渲染同步 | 同一 tick、同一 SimTime | 文件名时间戳比标签晚 ~106 ms（数据集自带） | 仿真无延迟 |
| **机头方向（标签 x）** | **网格真实机头 = 标签 −y（7 个机型全部）** | 标签 x = 机头（云台 / 红色前臂灯） | **不一致 → 已修正（S2/S3）** |
| **物理尺度** | **网格比真机大 1.25~2.5 倍** | 真机 | **不一致 → 已修正（S3）** |
| 翻转增广镜像面 | 按标签 y 镜像，但真实对称面是标签 x → 翻转样本航向再差 180° | 正确 | 随机头修正自动变正确 |
| 视角覆盖 | 标签系下无正面（az∈(−60,60) 为 0）；修正后缺的是左侧，翻转补齐 | 全方位 | 修正 + 翻转后覆盖完整 |
| 中心定义 | 包围盒几何中心 | VICON 刚体原点（phantom4 官方框中心在其下 5.5 cm；mavic2 官方框中心在其后 8.3 cm、下 4 cm） | 不一致，未修（厘米级） |
| 尺寸标签 | 各机型 BoundingCheck 盒（含桨） | 两个机型都固定 0.34×0.34×0.23 | 不一致，未修（只影响尺寸项） |
| 机型 | 7 型，含 phantom4、mavic-mini | phantom4、mavic2（仿真里没有 mavic2） | 数据覆盖差异 |
| 桨叶外观 | 静止、清晰可见 | 高速旋转、几乎不可见 | 外观差异，未修 |

## 1. 仿真网格机头与标签差 90°（主因）

录制器把 BoundingCheck 盒局部 +X（= actor +X = 飞行方向）写成标签 x。录制器代码本身没错，核对了飞行方向：7 型标签 x 与速度方向的偏航差中位数都是 0.00°。
问题出在资产：Drone Pack 的 7 个网格，真实机头都朝 actor +Y，也就是标签 −y。

证据（`output/camnorm/annot_audit/`）：
- **顶点镜像对称**（`sim_assets/verts`，UE 无头导出）。6 个网格关于 X=0 镜像对称，所以侧向轴是 X。unk3 蓝图把网格转了 −90°，转完也一样。
- **侧剖面**（`sim_assets/mesh_profiles.jpg`、`unk3_slice.jpg`）：
  - avata2 的镜头在 +Y 端。
  - phantom4 的云台相机在 +Y，下视视觉传感器在 −Y。
  - mavic-mini 位置更低、间距更宽的后臂电机在 −Y。
  - m210 和 m300 的云台挂在 +Y。
  - unk3 机身 −Y 端高而圆，+Y 端低而尖。
- **原图裁块**（`nose_views/*.jpg`）：
  - 标签“正后方”视角看到的都是起落架纵向展开的侧视图。
  - phantom4 在标签 −y 侧看到云台镜头正对相机。
  - M600 的红色前臂在 +Y 侧。
- **修正后的正面视角**（`label_fix/front_views_new_axes.jpg`）：phantom4、m210、unk3 都是镜头正对相机、起落架左右分开，新 x 轴指向相机。

后果：
- 标签 x 实际是机体侧向。零样本角度误差集中在 ±60~120°（73%）与此吻合。
- 翻转增广按标签 y 镜像，而真实对称面是标签 x。翻转样本的航向因此再差 180°。
- 仿真 test 只有未翻转视角，所以域内角度误差仍然只有 5°，看不出问题。

修正（`uavdet3d/utils/sim_asset_fix.py`）：R' = R·Rz(−90°)，即新 x = 旧 −y，同时 l、w 互换。

## 2. 仿真网格物理尺度偏大

对针孔相机，把物体的位置和尺寸一起除以 k，投影逐像素不变。所以标签变换 t/k、lwh/k 与图像严格一致。
自检结果：缩放前后归一化投影最大差 9.6e−8。

## 3. 其他核对（未改动）

- **中心**。背景差分测量（`measure/summary.json`）结果如下，这是厘米级，对零样本米级误差不是主因，记录待迁移阶段考虑：
  - MAV6D phantom4 的可见质心在 VICON 原点下方约 2.6 cm。
  - 仿真 phantom4 的可见质心在盒中心上方约 3.5 cm。
  - mavic2 的 VICON 原点比可见机身中心偏前约 4 cm。
- **MAV6D 官方 2D 关键点**（labels_yolo6d）。mavic2 用的是另一个框（0.284×0.333×0.120，中心偏移 (−0.083, 0.005, −0.040)），我们的缓存对两型都用了 phantom4 的 0.34 框。这只影响尺寸标签和 ADS 尺寸项。
- **录制器路点**。LegacyEllipse 模式沿相机前向从近到远，循环时瞬移回起点，所以无人机总是远离相机飞。机头修正后，这种飞法等价于“侧飞远离”，视角由右侧、正面、背面组成，左侧靠翻转补齐。
- **`build_mm_cache.py --lidar-offset` 默认 6**。这是旧 CARLA 的延迟补偿，而新录制器所有模态同 tick。indoor8 是 RGB-only，不受影响。以后为新数据建深度/tag 缓存时要设为 0。

## 5. 是不是正好 90°、是不是系统性的、旧 CARLA 数据有没有

- **角度**：从顶点拟合每个网格的左右对称面方向，扫 0~180°，结果是 avata2 90.0、mavic-mini 90.0、phantom4 90.0、unk3 89.9、m210 90.0、m300 89.8（°）。对称面与网格坐标轴重合在 0.2° 以内，所以偏差只能是 90° 的整数倍，正负号由机头特征定。M600 是六旋翼，90° 和 180° 同样对称，只能靠红色前臂判断。
- **系统性**：蓝图里网格相对 actor 的旋转固定（6 型为 0，unk3 为 −90°），包围盒相对旋转为 0。标签 x 逐帧跟随 actor +X，与飞行方向的偏差中位 0.00°。所以同一机型每一帧都是同一个常数偏差，不是随机噪声，是资产建模朝向（机头沿 Y）导入 UE 时没有转到 X 造成的。
- **采集代码**：旧 CARLA 的 UDataLogger.cpp 与新 UavRecorder.cpp 都记录 BoundingCheck 盒 8 个角点，角点顺序相同。盒子本身正确，修正前后 8 角点集合不变；错的是转换时把 c1−c0（盒子局部 X）当机头。
- **旧数据**：旧 CARLA 工程 `D:/BaiduNetdiskDownload/carla_whole/carla/.../Drone_Pack/Drone_Bp/test_drones` 与新工程的 10 个蓝图、7 个网格 uasset 的 MD5 全部相同；旧数据 boxes_rgb 里的 actor 名是 `BP_Drone01_m210-rtk_8`、`BP_Drone01_drone-unk3_14` 等。因此旧 UAV-MM3D 标签有同样的 90° 机头偏差和同样的网格偏大。旧数据原图多为夜景远距离，目视无法独立确认（`old_carla/old_nose_views.jpg`），结论依据是资产逐字节相同 + 采集代码相同。
- **影响**：只在旧数据内部训练和测试时，训练集和测试集偏差一致，朝向指标本身自洽；但“朝向”的含义是 actor 前向而不是视觉机头。凡是涉及真实数据迁移、与真实标签对比、或按标签左右轴做翻转增广的实验都会受影响。

## 11. P1（真机尺寸重采）零样本没变好：深度误差的真正来源是「机队尺寸分布」，不是单机标签

P1 用重采的 PowerPlant（真机尺寸 + 原生机头 +x）训练，域内极好（仿真验证 det 0.93 / 位置 0.29 m / 角度 12.8°），
但 MAV6D 零样本与 S1 基本持平：位置中位 4.287 m（S1 4.041）、角度中位 90.0°。逐条排除：

| 假设 | 检验 | 结论 |
|---|---|---|
| 单位 / 焦距 | `diag_units.py` | 早已排除（自洽 1.02） |
| 虚拟深度 Zv 覆盖不到 MAV6D | P1 在自己仿真 test 上扫裁窗 x1.0~x4.0：Zv 11.4→2.67，深度比 0.99/1.01/1.04/0.99/1.01 | **排除**。Zv 2.67 比 MAV6D 的 3.56 还近，且 s_px 64.6 ≈ MAV6D 61.7 |
| 真实数据标注有错 | 用 MAV6D 自带 `labels_yolo6d` 的 2D 关键点（含畸变）与我们缓存 GT 投影对比 | **排除**。phantom4 跨度比 1.00，中心差 8.4 px = 已知的官方角点中心偏移 0.055 m 在 Z=3.4 m 上的投影（0.055×492/3.4 = 8.0 px） |
| 模型根本不看目标像素大小 | MAV6D 上围绕目标裁放 z=0.6/1.0/1.6/2.2（真实深度不变） | **部分排除**。预测公制深度基本不随 z 变（P1 5.1/8.3/5.1/5.3 m），说明它在读像素大小 —— 只是把这个大小配给了错误的物理尺寸 |

**真因（已证实）**：模型的深度 = 像素大小 × 它认为的物理尺寸；而它在真实图上认不出是哪架机，两个头都塌回训练集先验。

- 仿真域内，尺寸头完全由外观驱动、跨 10 倍量程精确：avata2 0.265→0.273、phantom4 0.531→0.53、unk3 0.446→0.426、m210 1.274→1.285、M300 1.563→1.578、M600 2.587→2.591（比值全是 1.00±0.01）。
- MAV6D 上尺寸头塌成常数：**S1 输出 0.822 ≈ 它训练集对角线中位 0.829（四分位距仅 0.055，几乎逐帧同一个数）**；P1 输出 0.534 ≈ 它的中位 0.531（四分位距 0.504，还有一点响应）。
- 深度头的先验更大：反推「模型假设的画面跨度」L_imp = 0.923 m（P1）/ 0.897 m（S1），真值 0.42 m —— 比值 2.21 / 2.05，正是观测到的深度比。

训练集机型尺寸分布（框对角线）：

| 缓存 | 中位 | 均值 | 各机型（数量, 对角线 m） |
|---|---|---|---|
| P1 `pp_realsize` | 0.531 | **0.971** | avata2 (1323, 0.265)、mavic-mini (1353, 0.383)、unk3 (1135, 0.446)、phantom4 (1343, 0.531)、m210 (1366, 1.274)、M300 (1259, 1.563)、**M600 (1088, 2.587)** |

| MAV6D test | 0.533 | 0.533 | 只有 phantom4 / mavic2，官方角点 0.34×0.34×0.23 |

7 个机型里有 3 个是大机（m210 1.27 / M300 1.56 / M600 2.59 m），把均值抬到 0.97 m；MAV6D 全是 0.533 m 的小机。
真机尺寸修正让**每架机的标签**对了（这是对的、必须做的），但没有改变**机队构成**，所以先验仍然偏大约 2 倍 —— P1 ≈ S1。

**另有一处模型自身的不一致**：depth 头与 dim 头各自独立回归，没有任何几何耦合。
P1 在 MAV6D 上尺寸头已经给对了（0.534 vs 真值 0.533），深度头却按 ~1.15 m 在算。
若深度改为由「预测尺寸 + 预测 2D 跨度」几何解出（需新增一个 2D 尺寸头），P1 的正确尺寸先验就能直接转成正确深度。

**下一步（按性价比排序）**：
1. 机队配比：只用小机（avata2 0.265 / mavic-mini 0.383 / unk3 0.446 / phantom4 0.531，均值 ≈ 0.41）训一臂，先验直接对上 MAV6D 量级 —— 用现有数据即可，不必重采。
2. 几何耦合：加 2D 尺寸头，深度 = f × L_3d / s_2d，让尺寸先验与深度自洽。
3. 外观域差：根因是真实图上认不出机型（S1 的尺寸输出四分位距 0.055 = 完全塌掉）。这是后续多场景数据 + 增广要解决的。

诊断脚本：`tools/annot_audit/diag_p1.py` / `diag_p1b.py` / `diag_zv.py` / `diag_zoomreal.py` / `diag_prior.py` / `sheet_appearance.py`。

### 11.1 几何解耦的上界检验（不重训，用 GT 的 2D 跨度当作「完美 2D 尺寸头」）

对每个匹配上的目标，丢掉深度头的输出，改用「模型自己预测的尺寸 + 姿态」和观测到的 2D 跨度解深度
（Z = f × L_perp(预测 lwh, 预测 rot) / s_2d），再沿 2D 中心的射线还原 xyz：

| 臂 | 现在（深度头直接回归） | 几何解耦后 | 深度比 |
|---|---|---|---|
| P1（真机尺寸） | 位置中位 **4.601 m** | 位置中位 **1.012 m** | 2.21 → 1.13 |
| S1（旧标签） | 位置中位 3.651 m | 位置中位 2.099 m | 2.05 → 1.61 |

两点结论：
1. 深度头是唯一的瓶颈 —— 同一个模型的尺寸/姿态输出已经足够解出 4.5 倍更准的深度。
2. **真机尺寸修正是有效的，只是被深度头挡住了**：解耦后 P1 1.01 m vs S1 2.10 m，尺寸修正值 2 倍。
   S1 解耦后仍差，是因为它的尺寸先验本身就错（0.822 vs 真值 0.533）。

注：上界用 GT 的 2D 跨度，真实实现要学一个 2D 尺寸头（2 通道 log w2d/h2d，L1 对齐 GT 投影框）。
2D 尺寸是纯 2D 检测量，跨域迁移远比公制深度容易，但学出来不会是完美的，实际收益会低于这个上界。

## 14. 域泛化方法（2026-09-16，用户定：目标是纯仿真零样本可用）

诊断结论是「特征绑死在仿真外观上，换域后所有头塌回先验」—— 这是标准的**域泛化**问题，
而本项目此前几乎没用过这套工具箱（一直在修标签和几何，那些是真 bug 但不治这个）。

| 标准做法 | 本项目此前 |
|---|---|
| ImageNet 预训练骨干 | ✗ ResNet8x 从零训，只见过 2 万帧仿真图 |
| 域随机化（纹理/材质/光照/相机） | ✗ 场景固定、材质固定、每场景一套灯光 |
| 特征统计随机化（MixStyle） | ✗ |
| 归一化层选择（IN/GN） | ✗ |
| 关键点+PnP 而非回归深度 | 仓库里有 `KeyPoint2Pose` + `PnP_im_points_to_boxes9d`，没接到 camnorm |
| 无标签目标域校准 | ✗（AdaBN 实测有效，未进流程） |

### 14.1 MixStyle（`model_utils/mixstyle.py`，骨干 stage 1/2 之后）

对每个样本算逐通道实例统计量 (mu, sigma)，按自己的归一化后，用「自己的」与「批内另一样本的」
统计量的随机凸组合还原（lam ~ Beta(alpha,alpha)）。只在训练时生效，推理恒等，不加参数。

为什么对症：AdaBN 证明失败主因之一就是特征统计量跨域漂移（P1 位置 4.593 → 1.679 m）。
AdaBN 是事后补救且需要目标域数据；MixStyle 在训练时堵死这条捷径，**只用源域**。
「风格」在这里恰好包含【细节强度】这一轴 —— 就是仿真被放大 1.32 倍后掉到真实 1/16 的那个量。

配置 `MODEL.BACKBONE_2D.MIXSTYLE: {p, alpha, layers}`，`p<=0`（缺省）= 完全关闭。
自检：训练态改变激活、推理态恒等、p=0 时训练态也恒等。

### 14.2 ImageNet 预训练骨干（`TvResNet`，早已实现但**从未评过**）

S1 的尺寸头在 4800 帧真实图上输出**恒定 0.822，四分位距仅 0.055** —— 它在真实照片上完全分不出机型；
而在仿真里跨 0.265~2.587 m 十倍量程比值全是 1.00。19M 网络从零训在 2 万帧单一渲染器图上，
学到的必然是那个渲染器的纹理。ImageNet 特征来自 120 万张真实照片，这是 sim2real 最基本的一步。

新增 `FREEZE_BN`：把骨干 BN 锁在 ImageNet 的 running statistics 上（train() 时也不更新、不学仿射）。
动机同上 —— 在仿真上微调会把 BN 统计量拉回仿真分布，白白丢掉那份「真实照片」的统计量。
实测锁上后 43 个 BN 里只剩 7 个（FPN 出口 2 + 头 5）处于训练态。

### 14.4 一个已知的取舍：`no_upscale` 不是净赢

去掉放大同时也去掉了「够得到 MAV6D 工作点」的样本：训练 Zv 与 MAV6D 的分布重叠
**0.473 → 0.361**，Zv<3.52 的样本占比 18.4% → 8.6%。历史上踩过 Zv 外推的坑
（配置注释：只训整幅缩放时裁成 z=2.5 深度就偏大 2.1 倍）。

解法是把网络输入调窄（不放大的裁窗上限 = 源宽/输入宽，真实域的 Zv 也随 f_in 抬高）：

| 网络输入 | 裁窗上限 | MAV6D Zv中位 | 重叠 | 目标跨度 |
|---|---|---|---|---|
| 512×288 | z≤2.50 | 3.52 | 0.231 | 77 px |
| 384×216 | z≤3.33 | 4.69 | 0.380 | 58 px |
| 256×144 | z≤5.00 | 7.04 | **0.555** | 38 px |
| *现状 512 + 允许放大 z≤4* | — | 3.52 | *0.473* | *77 px* |

**所以现在这版 F1（512 + no_upscale）两头不靠**，要么保留放大只加带宽增广，要么降输入宽度
（需按新分辨率重建 MAV6D 缓存）。那个布尔开关也该推广成「窗口最小比例」，允许中间档。

## 15. 两个无人机特有的外观缺失（2026-09-16，放大目视 + 统计）

比「域随机化」这类大词具体得多，而且都是资产级小改动，不是重采整个数据集的量级。

### 15.1 红色前臂 LED：真实有，仿真完全没有

目标框内「饱和红色像素」（r>140 且 r−g>45 且 r−b>25）占比 > 0.1% 的帧：

| | 帧数 | 有红像素的帧 |
|---|---|---|
| 真实 MAV6D | 120 | **41%** |
| 仿真 PowerPlant | 54 | 9%（而且是背景锈管，无人机本身一个都没有） |

**这恰恰是机头指示灯。** 当初确认「MAV6D 两型标签 x = 机头」用的判据就是「云台 / 红色前臂灯」（§ 2026-09-15）。
也就是说：**真实图里最可靠的朝向线索，在仿真里根本不存在**。模型只能靠机身轮廓猜朝向，
而四旋翼机身前后近似对称 —— 这直接对应零样本朝向误差 65~90°（接近随机）。

修法：给仿真无人机加发光材质的前臂 LED，并随机化开关 / 颜色 / 亮度。蓝图里加一个 emissive 材质的量级。

### 15.2 桨叶：真实是运动模糊的半透明条，仿真是静止实心叶片

录制器里**没有任何桨叶相关代码**（grep Propeller/Rotor/Blade/Spin 全空），桨是静止的。
放大目视：仿真是 4 片清晰白色桨叶，占轮廓一大块；真实里被高速旋转模糊成几乎看不见。

模型在仿真里必然会用桨叶判机型和尺寸 —— 而真实图里这个特征不存在。
这直接对应「尺寸头在真实上输出常数（S1 恒定 0.822，四分位距 0.055）」。

修法：采集时转桨 + 开运动模糊；或随机隐藏桨叶 / 换成半透明盘。

证据图：`scratchpad/props_sim_vs_real.jpg`、`scratchpad/zoom_led.jpg`。

## 16. 2026-09-16 傍晚：可分离的两个失败 + 回归头的结构缺陷

### 16.1 零样本结果（纯仿真，MAV6D test 4800 帧）

| 臂 | 说明 | 2D 中心 px | 位置中位 m | 角度中位° | 折叠角° |
|---|---|---|---|---|---|
| P1 | ResNet8x，归一化常数写错 | 110.33 | 4.287 | 90.0 | 54.1 |
| P1b | ResNet8x，归一化已修 | 32.77 | 5.653 | 90.3 | 47.4 |
| **R1** | **ImageNet ResNet-34 + FPN** | **10.51** | 4.591 | **69.9** | **39.4** |
| S1 | 旧标签 8 场景（参照） | 9.36 | 4.041 | 90.9 | 76.6 |

**两个失败是可分离的，各自响应不同的修法：**

- **2D 定位 / 朝向 —— ImageNet 骨干大幅改善**：中心误差 110 → 10.5 px（追平 8 场景的 S1，而 R1 只有 1/5 数据、单场景），折叠角 54 → 39°（全场最好）。**图上直接可见的量能迁移。**
- **深度 / 尺寸 —— 所有臂都塌回训练先验，ImageNet 骨干也没救**。R1 预测尺寸对角线 1.150（真值 0.533）。**需要「量出目标表观大小」的量不迁移。**

### 16.2 误差形态：只有 S1 是纯标量

| 臂 | 深度线性拟合 | 除单个标量后位置中位 |
|---|---|---|
| S1 | `2.21×真值 − 0.27`（截距≈0，**纯尺度**） | **0.269 m**（ACC0.2m 0.388 / ACC0.3m 0.549） |
| R1 | `0.55×真值 + 5.96`（斜率塌了） | 1.083 m |
| P1b | `1.65×真值 + 1.98` | 0.952 m |

S1 的整个 3.7 m 误差就是一个常数——除掉就到可用线上。R1 的斜率只有 0.55、截距 5.96，
说明它的深度**几乎不随真值变化**，塌成了常数。两种都是「深度头不读真实图」的表现，形态不同而已。

### 16.3 结构缺陷：回归头没有 bias（已修，配置开关）

`center_dis` / `dim` / `rot` / `center_res` 四个头的输出层原本 `bias=False`，只有 `hm` 有
（`with_bias = (cur_head_name == 'hm' and ...)`）。于是常数部分（「典型深度」「典型尺寸」）
必须由特征产生 —— MAV6D 的深度真值是 0.147、变化范围只有 ±0.05，**预测里 80% 是典型值，
而这 80% 全从会跨域漂移的特征里长出来**。

**内部对照：五个头里唯一有 bias 的 `hm`，恰恰是唯一迁移得好的（2D 定位 84%、9.4 px）。**

注意：我一度用「头内激活求和」去证明「输出正比于激活幅值」，实测 dis 头 3.35 倍但 dim 头 0.70 倍
—— 权重有正负，激活求和不是正确的统计量，那个机械解释**不成立**，已作废。成立的是上面这条结构论证。

### 16.4 自洽标准化（已实现，`TARGET_NORM`）

`target = (量 − mu) / sigma`，mu/sigma 由 `tools/calc_target_stats.py` 从**训练集自身**算
（pp_realsize: DEPTH_MEAN 6.118 / STD 2.833；indoor8: 5.950 / 2.675；MAV6D: 3.486 / 0.868）。
解码时加回去 —— 常数永远不经过特征通路。`MAX_DIS` 与损失权重简并（`w·|p − Zv/M| = (w/M)·|p物理 − Zv|`），
单独改它等于改权重，所以不是「把 24 改小」而是「换成标准化」。

**配套修了一个会静默丢数据的坑**：前景掩码原本是 `gt['center_dis'] > 0`，标准化后真值有负数。
实测 **仿真 34.4% / MAV6D 100% 的前景格子真值为负** —— 不修的话这些目标会被当背景丢掉。
改成编码器另出 `fg_mask`（`check_target_norm.py` 会报这个比例）。

默认路径逐位未变。评测配置必须与训练结构一致（R1 第一次评测就因骨干不符被权重完整性检查拦下，42/179）。
