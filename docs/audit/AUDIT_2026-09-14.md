# 新室内仿真 → MAV6D 迁移：全链路审查（2026-09-14）

起因：用户质疑结果可靠性，逐项核查后发现多个会影响结论的错误。
原则：先把整条链路走完、问题找全，再统一定修法，最后才重跑训练。所有结论附可复现的核验。

## 审查范围（按数据流）
1. 仿真采集 → 数据集文件（UavSim 录制器，D:/data_collect）
2. 数据集 → 子集清单（build_near_subset.py）
3. 子集 → 缓存（build_mm_cache.py）
4. 缓存 → Dataset（MMCache_Det_Dataset：归一化 / 过滤 / 增广）
5. Dataset → 预处理 → 编码器（MAX_DIS / MAX_SIZE / 旋转 / 投影）
6. 模型与损失
7. 预训练权重 → 迁移初始化（train.py load_params）
8. 目标域 MAV6D Dataset（标签 / 尺寸 / 畸变 / 内参）
9. 评测（eval_on_mav6d.py / eval_ads_mav6d.py）
10. 训练协议（基线同代性 / 种子 / 取哪轮权重）

### P22（新，2026-09-14 17:30 发现）翻转增广的旋转标签把机头机尾对调
- 现象：第一轮 camnorm 实验里 MAV6D 从零训练的测试角度误差中位 93–113°（1% / 5% 档），而位置正常。
- 原因：翻转后旋转标签用了 R' = M R M。镜像后的目标要写成【同一个物体】的真旋转，必须用物体自身的镜像对称面 S：R' = M R S。
  无人机左右对称（机体 y）、前后不对称（云台在前），应取 S = diag(1,-1,1)；M R M 等于取了前后对称面，与正确值差绕机体 z 180°。
  hflip 概率 0.5 -> 一半训练样本的朝向标签错 180°。（MAV6D 旧数据集的 `_augment` 也是同一写法，但旧实验里没开。）
- 为什么回归测试没抓到：合成测试用的是长方体角点，长方体前后对称，分不出机头机尾。
- 修复：`camera_geometry.hflip_rotation`（R' = M R S，S 由配置 FLIP_BODY_MIRROR_AXIS 给，缺省 y），两个数据集都改。
- 新增测试：`flip_rule`（真实数据集 _augment：翻转后机头 = 镜像机头、机顶 = 镜像机顶）；
  `mut_flip_x`（变异测试：旧的 M R M 必须被判失败，实测角点偏差 161.75 px）；角点编号置换改为只接受机体 y 取反。
  真实 MAV6D 帧上翻转前后画机体轴核对：翻转后 x 轴仍指向云台（`output/camnorm/vis/flip_chirality_check_fixed.jpg`）。
- 影响：第一轮已跑的 S0 预训练与 C_p001_s0-2、C_p005_s0-1 全部作废，移到 `output/camnorm/_invalid_flip_20260914/`，全部重跑。
