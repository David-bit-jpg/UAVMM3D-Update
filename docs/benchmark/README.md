# Sim→Real 无人机 6-DoF 位姿估计迁移基准

两件事：**(1) 把「仿真源域 → 真实目标域」的迁移做成一个可复现的基准；(2) 在这个基准上
设计迁移方法。** 本文档定义基准本身——数据、协议、指标、基线，以及一节对域差异的客观刻画。

---

## 1. 两个域

| | 源域 · UAV-MM3D (仿真) | 目标域 · MAV6D (真实) |
|---|---|---|
| 来源 | CARLA 采集，本组自建 | 西湖大学，室内 VICON + 徕卡全站仪真值 |
| 场景 | 户外，多地图多光照 | 室内单房间，固定相机 |
| 机型 | 7 种（0.5–2.6 m） | 2 种（Mavic 2 / Phantom 4，均 0.34 m） |
| 每帧目标数 | 1–7 | 1 |
| 标注 | 9 点 3D 框（世界系） | 位置 + 四元数（VICON 系） |
| 模态 | RGB / 深度 / 语义 / 激光 / 毫米波 | RGB |
| 本基准使用 | **仅 RGB** | **仅 RGB** |

源域用近距离子集（见 §2），因为原始源域深度中位 42 m，与目标域的 3.2 m 差一个数量级，
直接迁移连尺度都不在一个量级上。

**规模**

| | 序列 | 训练帧 | 测试帧 |
|---|---|---|---|
| 源域 near15 子集 | 310 | 8,773 | 2,361 |
| 目标域 MAV6D | — | 15,202 | 4,800 |

目标域切分沿用官方 split（去重 + 过滤后）；源域**按序列切分**，避免相邻帧泄漏。

## 2. 源域子集的构造

`tools/build_near_subset.py` 两阶段筛选：

1. **粗筛** —— 用 `distance_info.txt` 的欧氏距离（快）
2. **精筛** —— 读 `boxes_rgb/*.pkl` 求真实相机系深度 Z

第二阶段不可省：实测存在欧氏距离很小但 **Z 为负**（目标在相机后方）的帧，编码器遇到
`Z<=0` 会直接跳过，留着就是一张空监督图。

```bash
python tools/build_near_subset.py build --root <data_collect> \
    --max-dist 15 --mode all --metric z --out-dir cfgs/subsets/near15
```

`--mode all` 要求整帧所有目标都在范围内；用 `any` 的话画面里仍会有几十米外的目标，
深度分布拉不回来。

工具另支持 `--metric angsize`，按**角尺度**（物体尺寸 / 深度，单位 rad）筛选。
理由见 §3.1——按距离筛只对齐了深度，机型尺寸一变表观大小又跑掉了。角尺度与内参无关，
是「表观大小」真正的不变量。

```bash
python tools/build_near_subset.py build --root <data_collect> --metric angsize \
    --max-dist 36 --mode all --min-ang 0.0724 --max-ang 0.2005 \
    --out-dir cfgs/subsets/angsize
```

默认区间 `[0.0724, 0.2005]` rad 取自 MAV6D 实测的 5%/95% 分位（0.34 m ÷ {4.70, 1.70} m）。

| 子集 | 筛选依据 | 序列 | 训练帧 | 测试帧 |
|---|---|---|---|---|
| `near15` | 相机系深度 Z ≤ 15 m | 310 | 8,773 | 2,361 |
| `angsize` | 角尺度 ∈ MAV6D 区间 | 166 | 3,012 | 657 |
| `angsize_single` | 同上 + 每帧仅 1 个目标 | 69 | 1,946 | 430 |

`angsize` 通过率只有粗筛的 3.6%：`--mode all` 要求整帧所有目标都在区间内，而一帧最多有
7 架尺寸相差 5 倍的无人机。`angsize_single` 进一步限定单目标，与 MAV6D 每帧 1 个目标一致。

**全库分布**（394,209 帧 / 1,310,301 个目标样本，每帧 1–7 个目标，单目标帧 55,305）：

| 距离阈值 | any（至少一个在内） | all（全部在内） |
|---|---|---|
| ≤ 8 m | 19,440 (4.9%) | 1,137 (0.29%) |
| ≤ 15 m | 56,782 (14.4%) | 7,685 (1.95%) |
| ≤ 30 m | 181,812 (46.1%) | 68,037 (17.3%) |

## 3. 域差异有多大（客观刻画）

`tools/domain_gap_stats.py`，两域各随机采 150 帧，同口径统计：

| 维度 | 源域（仿真） | 目标域（真实） |
|---|---|---|
| 图像分辨率 | 1280×720 | 1920×1080 |
| **水平视场角** | **90.0°** | **51.7°** |
| 目标深度 中位 [5%, 95%] | 11.29 m [3.87, 14.59] | 3.19 m [1.70, 4.70] |
| 目标物理尺寸 中位 [5%, 95%] | 0.70 m [0.51, 1.44] | 0.34 m（单一） |
| **目标像素大小（原生分辨率）** | **40 px** [25, 168] | **211 px** [143, 397] |
| 亮度 | 66.4 ± **60.5** | 117.6 ± **0.6** |
| 对比度 | 16.5 ± 11.2 | 61.4 ± 0.3 |
| 边缘密度 | 0.086 ± 0.084 | 0.389 ± 0.004 |
| 灰度熵 | 4.20 ± 1.99 | 7.53 ± 0.01 |
| 饱和度 | 56.6 ± 36.1 | 24.7 ± 0.4 |

三条结论：

### 3.1 表观大小差 2.84 倍，且可以精确分解

换算到网络输入空间（源域 1280→640，目标域 1920→512）：

```
表观像素 = 角尺度(rad) × 输入 fx
源域  : 0.0618 × 320.0 = 19.8 px   ->  热图(stride 8) 2.5 px
目标域: 0.1065 × 527.8 = 56.2 px   ->  热图(stride 8) 7.0 px
```

2.84 倍的差距由两个**相互独立**的因子相乘而成：

| 因子 | 比值 | 成因 | 可否消除 |
|---|---|---|---|
| 输入 fx | 1.65× | 视场角 90° vs 51.7° | **可以**，裁剪源域图到 621 px 宽即可让归一化内参相同 |
| 角尺度 | 1.72× | 源域目标更大但更远 | **可以**，把源域子集的筛选条件从「距离」换成「角尺度」 |

这直接解释了零样本臂的失败模式：CenterNet 的 `center_dis` 头学的本质是
「表观大小 → 绝对深度」的映射，而这个映射在两域间差了一个大常数因子。实测零样本
把 2.7 m 处的目标预测成 12.3 m。

### 3.2 目标域的外观方差几乎为零

MAV6D 亮度标准差 **0.6**（均值 117.6，即 0.5%），边缘密度标准差 0.004。
**它实质上是一个单场景数据集**：一个房间、一套光照、一台固定相机。
源域的对应标准差是它的约 100 倍。

这是本基准当前最大的局限：**目标域窄到可以被从零训练的模型直接记住**。
因此现有设置能测「数据效率」，但测不出「域泛化」。要做成有说服力的基准，
第二个目标域接近必需（候选：MMAUD，但它只有位置真值、无朝向，只能做位置子指标）。

### 3.3 外观本身差异也很大

仿真是暗、低对比、低纹理（大量天空背景）；真实是亮、高对比、高纹理（室内）。

## 4. 跨域对齐（工程前提）

不做这些，两个域的权重根本对不上。五个维度：

| 维度 | 处理 | 实现 |
|---|---|---|
| 模态 | 源域裁到仅 RGB，`IM_NUM=1` | `MODALITIES: ['rgb']` |
| 骨干 | 两边同为 ResNet8x `[64,128,256,512]` | 配置对齐 |
| 检测头 | 同为 CenterHead，同 `HEAD_ORDER` | 配置对齐 |
| 深度尺度 | `center_dis` 输出层按 `MAX_DIS` 比例精确重标定 | `--pretrained_src_max_dis` |
| 旋转约定 | 源域原生 `zyx` → 统一到 MAV6D 的 `xyz` | `frame_convention.py` |

旋转约定这条不能省：`rot` 头 6 通道 = (cos, sin)×3，两边 a1 一个绕 z 一个绕 x，
不统一等于把第一和第三个旋转轴接反——实测同一组角按两种顺序解释，旋转差异中位 **134°**。

对齐后权重迁移率从 41/178（15.3%）升到 **170/178（96.9%）**，
只剩 `hm` 头因类别数不同（7 vs 2）不可迁。

另有两个正确性前提：

- `object_encoder_mav6d.py`：MAV6D 专用编解码器，与解码严格互逆
  （原编码器对 `(N,10)` 的二维 GT 会 IndexError，且其反投影带 CARLA 轴置换，对 MAV6D 不成立）。
  300 组随机样本往返位置误差 **0.0000 m**。
- MAV6D 内参/外参校验：20,002 帧上 GT 投影 100% / 99.9% 落在画面内，相机位姿波动
  0.41–0.61 mm，折算到中位深度的位置偏差 26.8/34.8 mm，相对 340 mm 的目标尺寸可忽略——
  官方 `read_truth_Rt` 里写死的 camera→VICON 外参对两个型号都成立。

## 5. 协议

### 5.1 实验臂

| 臂 | 源域数据 | 目标域数据 | 说明 |
|---|---|---|---|
| **A** 零样本 | ✓ | ✗ | 迁移的**下限** |
| **B** 朴素微调 | ✓ | ✓ | 载入源域权重后全网络微调 |
| **C** 目标域从零 | ✗ | ✓ | 迁移的**基准线**，B 必须超过它才算有效 |
| **P** 冻结骨干探针 | ✓ | ✓（仅训头） | 诊断：源域特征本身能用到什么程度 |

### 5.2 目标域数据量档位

迁移的价值只在目标域数据稀缺时体现，所以数据量是本基准的主轴。
用 `SAMPLED_INTERVAL` 对训练集做等间隔降采样（等间隔而非取连续片段，保证覆盖全部序列）：

| 比例 | 间隔 | 训练帧 | 轮数 |
|---|---|---|---|
| 1% | 100 | 152 | 80 |
| 5% | 20 | 760 | 40 |
| 10% | 10 | 1,520 | 30 |
| 25% | 4 | 3,800 | 12 |
| 100% | 1 | 15,202 | 15 |

测试集恒为完整的 4,800 帧。

### 5.3 指标

各臂 `hm` 通道数不同（源域 7 类 vs 目标域 2 类），无法直接用各自配置的评测流程横向比，
故统一成**类别无关**的位姿误差（`tools/eval_on_mav6d.py`）：每帧取置信度最高的检测，
与 GT 比：

- 位置误差 / 深度误差（米）：中位、均值、90% 分位
- 旋转误差（度）：测地距离 `‖log(R_pred⁻¹ R_gt)‖`，中位、均值、90% 分位
- 准确率：位置误差 < {0.1, 0.2, 0.5, 1.0} m，角度误差 < {5, 10, 20}°
- 有效检测数 / 总帧数

`--json` 输出机器可读结果，`tools/plot_lowdata_curve.py` 汇总成曲线。

### 5.4 复现

```bash
# 源域预训练（约 4.5 小时，单卡 RTX 5090 Laptop）
python tools/train.py --cfg_file cfgs/models/uavdet_3d/laam6d/centerdet_rgb_near15.yaml \
    --batch_size 8 --workers 4 --epochs 30 --set DATA_CONFIG.DATA_PATH <data_collect>

# B 臂（某个数据量档位）
python tools/train.py --cfg_file cfgs/models/uavdet_3d/mav6d/centerdet.yaml \
    --batch_size 8 --workers 4 --epochs 40 --extra_tag B_p05 --fix_random_seed \
    --pretrained_model <sim_ckpt> --pretrained_skip hm --pretrained_src_max_dis 15 \
    --set DATA_CONFIG.DATA_PATH <MAV6D> DATA_CONFIG.SAMPLED_INTERVAL.train 20

# C 臂：同上，去掉 --pretrained_* 三个参数
# P 臂：在 B 臂基础上加 --freeze backbone_2d（可选 --freeze_bn_stats 连 BN 统计量一起冻）

# 统一评测
python tools/eval_on_mav6d.py --ckpt <ckpt> --tag <tag> --json <out>.json
python tools/plot_lowdata_curve.py --metric pos_median
```

## 7. 已知局限与代码缺陷

### 7.1 基准层面

1. **目标域是单场景**（§3.2）——最需要补的一条。
2. **只有一个目标域**——MMAUD 可作第二个，但它无朝向真值。

### 7.2 训练/损失层面（`tools/loss_term_audit.py` 实测）

在 C 臂最终权重上跑 25 个 batch，逐项拆开 `CenterHead.get_loss()`：

| 损失项 | 均值 | 标准差 | 占总损失 |
|---|---|---|---|
| **hm** | 0.2743 | **0.0005** | **88.8%** |
| center_res | 0.0187 | 0.0119 | 6.1% |
| center_dis | 0.0033 | 0.0013 | 1.1% |
| dim | 0.0003 | 0.0002 | 0.1% |
| rot | 0.0121 | 0.0028 | 3.9% |

3. **总损失的 89% 是热图项，且它是近乎常数的地板**（标准差 0.0005）。
   因此**不能用总损失横向比较两个臂**——差异被这个常数淹没。
4. **热图损失归一化有问题**：分子对全部像素求和、分母只除以正样本数
   （实测正样本中位 100，而元素总数约 16000），背景项被放大约 160 倍。
   反推每个元素的平均 BCE 约 0.0017，说明背景已被压到接近饱和、几乎没有梯度，
   却仍占着总损失的绝大部分。原版 CenterNet 用 focal loss 正是为了压住简单负样本。
5. **五项等权相加，没有任何 loss weight**：rot 只占 3.9%，dim 占 0.1%。
6. **`dim` 头对 MAV6D 学的是常数**：`box9d = concat(t, self.obj_size[0], euler)`，
   两个型号共用同一个 `OB_SIZE`，输出的尺寸不是估计出来的。
7. **图像归一化只有 `/= 255`**，没有减均值除方差。源域亮度 66、目标域 118，
   第一层卷积看到的输入分布差很多；按域各自统计量归一化是几乎免费的收益。
8. **回归损失用 `torch.abs(gt) > 0` 判前景**：真值恰好为 0 的位置会被丢掉
   （`cos(±90°)`、中心落在整像素时的 `res`）。正确做法是用热图峰值位置索引。

### 7.3 数据层面

9. **数据增广是死配置**：`mav6d.yaml` 里写了 `image_flip` / `image_rot`，
   `DatasetTemplate.__init__` 也构造了 `self.data_augmentor`，但**全仓库无一处调用**。
   两个 dataset 的 `__getitem__` 只调 `data_pre_processor`。训练实际是**零增广**。
   （另一面是走运：该增广的 `DATA_LIST` 只含 `image`/`heatmap`，不同步变换 3D 标签，
   真跑起来会破坏旋转真值。）
10. **欧拉角参数化会退化**：`as_euler('xyz')` 在中间角 a2 接近 ±90° 时万向锁，
    (a1, a3) 不再唯一。MAV6D 训练集实测 |a2| > 80° 占 **9.5%**、> 85° 占 3.4%，
    这部分数据的监督是自相矛盾的。cos/sin 编码解决了 ±180° 绕回
    （a3 有 31% 的帧 |a3| > 170°，这部分处理正确），但解决不了万向锁。
    建议换 6D 连续旋转表示——同样 6 个输出通道，改动局限在编解码与损失。
11. **源域 `MAX_SIZE` 曾误设为 2**，导致最大机型 Matrice-600-Pro 的归一化尺寸目标
    超出 [0,1]。已改为 4；该机型的源域内数字需用修正后的配置重训才准确
    （其余六类不受影响）。

### 7.4 评测口径

12. `tools/eval_on_mav6d.py` 的角度误差是**不折叠对称性**的测地距离；
    而仓库自带的 `uavdet3d/datasets/mav6d/eval.py` 里
    `val_rotation_enler(..., fold_180=True)` 默认把 >90° 的误差折成 180−err。
    两个口径不可比，四旋翼外观上接近 90° 对称，折不折会显著改变数字。**应两个都报。**

### 7.5 其他

13. **`--use_amp` 是空开关**：参数接受但 `train_utils` 里没有 autocast/GradScaler。

### 7.6 已验证无问题

- `object_encoder_mav6d` 编解码严格互逆（300 组随机样本位置往返误差 0.0000 m）
- `sigmoid` 在解码前施加，`SCORE_THRESH` 比较的是概率而非 logit
- `center_dis × MAX_DIS` / `dim × MAX_SIZE` 反归一化正确
- MAV6D 内外参已在 20,002 帧上验证（§4）

## 8. 多模态源域子集与跨模态蒸馏管线

前面的实验把「RGB 单模态迁移为什么失败」钉在了两个轴上：**天气/外观**与**尺寸/距离**。
仿真数据恰好有两个 RGB 没有的模态各管一个——IR（对光照/天气不敏感）与 LiDAR（直接给几何）。
但 MAV6D 与部署都只有 RGB，所以走 **多模态教师 → 跨模态蒸馏 → RGB 学生 → 迁移** 的路线
（与 MM'26《Beyond RGB》的 Stage 1 同构，区别是我们的模态是同一时刻成对的，教师可以真的吃多模态输入）。

### 8.1 源域子集 mm20（`tools/build_mm_subset.py`）

不再为对齐 MAV6D 的深度分布而苛刻筛选，而是**保留仿真的丰富性**（多目标、8 种天气、5 个批次），只要求：
一帧里至少一个目标 (1) 到相机距离 ≤ 20 m，(2) 在相机前方，(3) 8 个角点全部投影在画面内；
且 rgb / ir / lidar 三个文件齐全（LiDAR 取 +6 帧的配对点云，序列末 6 帧无配对，丢弃）。

| | 序列 | 帧 |
|---|---|---|
| 粗筛（任一目标欧氏距离 ≤ 23 m）| 1,176 | 120,375 |
| 精筛后 | 1,082 | **79,055** |
| train / test（按序列 8:2）| 866 / 216 | 62,417 / 16,638 |

按天气：clear_day 6,069 · clear_night 12,265 · fog_day 7,954 · fog_night 14,426 · rain_day 7,706 ·
rain_night 14,537 · snow_day 7,518 · snow_night 8,580（**夜间占 63%**）。每帧目标数 1–7，
最近合格目标距离中位 14.9 m [5%: 6.0, 95%: 19.6]。

### 8.2 三条关于传感器的实测事实

1. **`LIDAR_OFFSET = 6` 在五个采集批次全部成立。** 用 tag==1 点簇的 3D 均值投影对框中心，扫偏移 0–8：
   偏移 6 的中心偏差中位 2 / 13 / 9 / 7 / 35 px（No-MotionBlur / Town01 / 03 / 07 / 10），偏移 0 为 164–255 px。
2. **LiDAR tag 通道 = 打在无人机上的点**，是免费的逐点分割标签。
3. **LiDAR 测距噪声 NoiseStdDev 是逐序列随机的**：{0, 2.5, 3.5, 4.5} m 四档混在每个批次里；
   mm20 中噪声 0 的帧 18,334（23%），其余 77% 噪声 ≥ 2.5 m。沿射线的噪声投到另一位置的相机里
   就是一条极线拖尾——**单点深度在多数序列里不可信，可信的是 tag 与点簇均值**。每帧的噪声值
   记录在子集文件第 7 列，训练时可按它筛或加权。

另：RGB / IR / DVS 三台相机横向相距约 2.4 m（同内参、纯平移），7 m 处视差约 240 px；
仓库原有的 `register_images_by_center` 按目标中心平移 IR 只对齐一个深度平面。

### 8.3 旧代码里的一个几何 bug

`dataset_utils.convert_9points_to_9params` 用中心到 **两个角点（对角线）** 的方向当坐标轴，
而 `convert_9params_to_9points` 把角度当成真正的框轴——二者**不互逆**，随机姿态往返旋转误差最大 **146°**。
源域 rot 头因此学的是 R∘F(l,w,h)，一个随长宽比变化的"假旋转"；源域内参数比参数看不出来，
迁到 MAV6D（VICON 真旋转）就是系统性负迁移的又一个结构性原因。
实测真实框的角点顺序就是标准原型（c1−c0、c3−c0、c4−c0 两两正交，余弦 0.0000），
新管线直接由三条边解出真旋转与边长。

### 8.4 缓存与模型（`tools/build_mm_cache.py`、`uavdet3d/datasets/mmcache/`、`center_det_kd.py`）

HDD 直读三个模态只有 0.3 it/s，故打包为 512×288 的 memmap 放 SSD（每 3 帧取 1，train ≈ 21k 帧）：
`rgb` uint8 ×3、`ir` uint8（按最近合格目标深度处的视差平移到 RGB 视角）、
`depth` uint16 厘米（LiDAR 投影 z-buffer）、`tag` uint8。标签为相机系 9 参数，`MAX_DIS 40`、`MAX_SIZE 4`。

| 模型 | 输入 | 说明 |
|---|---|---|
| T 教师 | rgb+ir+depth+tag（6 通道） | 不部署，只用于蒸馏 |
| S0 学生 | rgb | 无蒸馏基线，也是迁移「B 臂」的来源 |
| S1-mm | rgb | 从 T 蒸馏 |
| S1-rgb | rgb | 从 S0 蒸馏（**自蒸馏对照**，区分多模态先验与蒸馏本身的收益）|

蒸馏项：特征 L2、GT 中心像素特征余弦（论文 RoI 项的 CenterNet 对应物）、热图软标签 BCE、
前景像素回归 L1、CrossKD（学生头接教师特征仍用 GT 监督）。三个 RGB 权重随后各自用**朴素微调**
迁到 MAV6D（1% / 5% / 10%），并各测一次零样本。

### 8.5 两条数据链路的逐步验证（`tools/verify_pipeline.py`）

用户要求"每一步都可视化验证，不能有对不齐、坐标变换错"。脚本对仿真与真实各跑一组数值检查并落图
（`output/verify/{sim,real}/`），结果（smoke 缓存 96 帧 + MAV6D 480 帧）：

| # | 检查 | 结果 |
|---|---|---|
| S1 | 角点→9 参数→角点（集合匹配）| 最大 **1.3e-5 m**。角点顺序与原型差一个顶/底面交换（映射 4,5,6,7,0,1,2,3），解码器按原型重建，顺序无关 |
| S2 | 编码器→解码器往返（仿真）| 位置 90% **1.2e-6 m**，旋转 90% **1.1e-6°** |
| S3 | 热图在 GT 中心格子的值 | 1−hm = **0**（37 框）|
| S4a | LiDAR 深度 vs 标注深度（噪声 0 序列，只看 tag 像素）| \|Δ\| 中位 **0.11 m**、90% 0.13 m —— 外参→世界→相机→像素整条链厘米级 |
| S4b | tag 像素落在 GT 框内 | 中位 **100%** |
| S5 | IR 平移后最近合格目标残差 | **0.00 px**；其余目标视差残差中位 77 px（2.4 m 基线的固有视差，属预期）|
| R1 | 编码器→解码器往返（MAV6D，带畸变）| 位置最大 **4.5e-7 m**，旋转 3.3e-6° |
| R2 | 热图在 GT 中心格子的值 | 1−hm = **0** |
| R3 | 畸变 k1=−0.231 对投影的影响 | 中位 3.2 px，**最大 47.9 px**（画面边缘）—— 编解码必须带畸变 |
| R4 | 跨域 `MAX_DIS` 重标定 | 输出比值恰为 15/8 = 1.8750，float32 误差 6.7e-4 |
| R5 | GT 中心投影在画面内 | **100%** |

两个曾经"未通过"的项都是**检查指标写错**而非链路错误：S1 逐槽位比较把顺序差异当成几何误差；
S4a 用整个框多边形取中位数会被框内几十米外的背景点淹没（框比无人机剪影大得多）。
